# AGENTS.md — universal working rules

Portable across projects; copy unchanged. Project specifics live in
**PROJECT.md** (auto-loaded via `opencode.json`); `README.md` and `docs/` are
the living documentation. If a `CLAUDE.md` exists, it is the legacy deep spec
for that repo — read it before changing behaviour. If a `DEV_STANDARD.md`
exists, it is the engineering standard; project-specific files win over it,
but say so explicitly when deviating.

## Ramp up

- Read PROJECT.md, then the README, then the docs the task touches. Prefer
  executable sources (config, scripts, lockfiles) over prose when they conflict.
- Find the module map / architecture note before writing code. New code goes to
  the module that owns it; if none does, propose a new module and update the
  map in the same change. Never append to the nearest plausible file.

## Architecture

- One source of truth per concept. A rule encoded in two places (e.g. backend
  and frontend) must share a constant or a test that pins them together.
- Pure core, dirty edges: domain logic is importable and testable without DB,
  network, or keys. I/O lives at the edges behind seams (auth, DB, storage,
  LLM) — a swap touches one module, not every call site. If a change spiders
  across files, stop: you are bypassing a seam.
- Replacement, not accretion: delete the path you replace in the same change.
  No `_old`/`_v2` suffixes, commented-out code, or callerless back-compat shims.
- Complexity budgets: a file over 400 lines or a function over 50 is a split
  signal — name it out loud, don't cross it silently.
- Schema belongs to migrations, never to startup DDL. Generated artifacts
  (OpenAPI, rendered pages, codegen) are regenerated by their script, never
  hand-edited.

## Typing

- Strict type checking is a gate, not a suggestion: run the project's
  typechecker (e.g. `mypy`, `tsc --noEmit`) and make it clean before done.
- No untyped escape hatches (`Any`, `any`, `@ts-ignore`, `# type: ignore`)
  without a written reason at the site. Type the boundaries: API payloads,
  model output, config.
- Match the surrounding strictness and idioms; don't loosen a config to make
  an error go away.

## Tests

- The suite must run offline: no network, no real API keys, no shared database.
  A test that needs a key means the design is wrong.
- Bug fixes start with a failing regression test. New behaviour ships with
  tests that pin it; put logic where the test environment can reach it.
- Run the focused test first, then the full suite. Single-test forms and any
  required services are in PROJECT.md — don't guess them.
- Never point a destructive test run (table drops, resets) at a real database.

## Definition of done

A task is done only when, and the reply states which were verified vs skipped:

1. lint, format and type checks clean;
2. tests pass offline;
3. the replaced code path is deleted;
4. the module map and docs match reality — docs move in the same change;
5. contract artifacts regenerated if the contract moved;
6. an ADR exists if an architectural decision was made or reversed — never
   silently contradict an accepted one.

Pipeline under OpenCode (no hooks run): implement → **reviewer** subagent →
**doc-writer** subagent. Use **architect** before changes that add modules,
move the data model, or alter a contract. Don't claim done without running the
checks; report what passed, what was skipped, and the remaining risk.

## Safety

- Never read, print, copy or commit `.env` or other secret files; use
  `.env.example` and placeholders.
- Don't commit or push unless explicitly asked.
- Verify commands and env vars exist before writing them into docs.
